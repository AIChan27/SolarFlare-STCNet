## 一、官方数据集到底给了什么

来源：<https://tianchi.aliyun.com/dataset/74780>
（页面是 JS 渲染的，正文可在 OpenI 镜像看到：
<https://openi.pcl.ac.cn/Cx/Solar-Flare-Forecasting-Dataset>）

官方说明原文要点：

> SOLAR-STORM2 contains **73,810 images** of sunspot group magnetogram
> with magnetic parameters and flare tags.
>
> The SOLAR-STROM2 dataset includes magnetogram file (**magnetogram.zip**)
> and magnetic parameter and flare tag file (**para_flare.txt**).

交付内容就是两个东西：

```
magnetogram.zip
  magnetogram_jpg/
    hmi.sharp_720s.1.20100504_160000_TAI.magnetogram.fits.jpg
    hmi.sharp_720s.1.20100504_173600_TAI.magnetogram.fits.jpg
    ...
para_flare.txt
```

**关键结论：官方数据集没有划分训练集/测试集，也没有提供任何预处理脚本。**
整个 73,810 个样本就是一个整体。论文里的训练/测试划分是作者自己做的。

这一点很重要，因为它意味着：**想复现论文，必须先自己实现划分逻辑，
而这段代码在官方数据和学长给的代码里都不存在。**


## 二、文件格式（官方定义）

### 文件名

```
hmi.sharp_720s.<num>.<YYYYMMDD>_<hhmmss>_TAI.magnetogram.fits.jpg
             ↑        ↑
             │        └─ 观测时刻（TAI 时间标准）
             └─ 太阳活动区编号（sunspot group number）
```

### para_flare.txt 的 12 列

官方原文：

> The first column is the filename of corresponding sunspot group image file.
> The 2-11 columns are ten parameters of the corresponding sunspot group.
> The 12 column is flare tag:
> **'1'** represents that this sunspot group is a flaring sample when
> **at least one given or greater flare happens within 48 hours** starting at
> the observation of the magnetogram.
> **'0'** represents a nonflaring sample when no given or greater flare
> happens within 48 hours.

| 列 | 内容 |
|---|---|
| 1 | 文件名（注意：**没有 `.jpg` 后缀**，实际文件是 `.fits.jpg`） |
| 2–11 | 10 个 SHARP 磁场特征参数 |
| 12 | 耀斑标签：1 = 48h 内发生 ≥ 指定级别耀斑；0 = 没有 |

10 个参数（论文表 2）：`TOTUSJH`、`TOTPOT`、`TOTUSJZ`、`ABSNJZH`、
`SAVNCPP`、`USFLUX`、`AREA_ACR`、`MEANPOT`、`SHRGT45`、`R_VALUE`。

论文 3.1 节把阈值明确为 **M 级及以上**：
> "1"表示在从磁图观测开始的 48 h 内至少发生一个 M 级或更大的耀斑。

（官方说明只写了 "given or greater flare"，具体级别由使用者在申请数据时指定，
论文用的是 M 级。）

## 四、论文的划分，以及论文数字的两处问题

论文 4.1 节原文：

> 训练集采取的是 **2010年5月–2015年10月以及2017年9月–2019年1月** 的数据。
> 为了解决正负样本不平衡问题，训练集在未发生太阳耀斑**每天的相同活动区样本中
> 只选择一条记录**，使其数量与发生太阳耀斑的样本量接近。经过负样本下采样后，
> 得到训练集**正样本数为2988个，负样本数为5073个**。
> 测试集采取的是 **2015年10月–2017年9月的原始数据**，
> 其中**正样本为196个，负样本为11852个**。

### 问题一：论文说数据集"3184 正 / 70822 负"，但实测是"2988 正 / 70822 负"

论文第 114 行：
> "两种类型的数据样本数分别为 **3184** 和 70822."

实测：

| | 论文 | 实测 | 差异 |
|---|---|---|---|
| 正样本 | 3184 | **2988** | 差 196 |
| 负样本 | 70822 | **70822** | 完全一致 |

负样本数**一个不差**，正样本差 **196**——而 196 恰好是论文自己说的测试集正样本数。

但论文又说训练集正样本 = 2988 = 实测的全部正样本数，
所以 2988 和 196 不可能同时从一个只有 2988 个正样本的数据集里取出来。

**结论：论文这个 3184 极可能是笔误**（或混入了别处的统计口径）。
以实测的 2988 / 70822 为准。

### 问题二：按论文时间段切分，实测样本数与他写的不完全一致

| 时间段 | 实测 正 / 负 |
|---|---|
| 训练段 A：2010-05-01 ~ 2015-10-01 | 2792 / 54673 |
| 训练段 B：2017-09-01 ~ 2019-01-31 | 49 / 4246 |
| 测试段：2015-10-01 ~ 2017-09-01 | 147 / 11963 |

论文写测试集"正 196 / 负 11852"，实测是"正 147 / 负 11963"，
两边都不完全吻合，差异不大（边界日期取闭区间还是开区间、个别样本归属不同都会造成）。

**不能完全复现论文测试集指标**，本项目按实测数据来做，并在文档里标明差异。


## 五、本项目的划分方案

### 训练集与测试集：完全照搬论文

```python
TRAIN_PERIODS = [("20100501", "20151001"), ("20170901", "20190131")]
TEST_PERIODS  = [("20151001", "20170901")]
```

### 负样本下采样：完全照搬论文规则

论文原文的规则是"**每天、相同活动区只选一条记录**"，
本项目实现为按 `(日期, 活动区编号)` 分组，每组随机保留 1 条
（`DOWNSAMPLE_NEGATIVE=True`，种子固定为 42 保证可复现）。

正样本**不下采样**（论文里正样本是全取的）。

下采样效果：

```
训练集负样本 50400 → 4342（4342 个"日期×活动区"组，每组留 1 条）
测试集不下采样（论文明确说测试集用原始数据）
```

### 验证集：本项目自行设计（论文没有提）

论文只说了训练集和测试集，没有验证集。但训练需要验证集做早停和选最优权重。

**第一版方案（失败）**：从训练段 B 的尾部切（2018-01 ~ 2019-01）。

失败原因：实测发现训练段 B 的 49 个正样本**全部集中在 2017-09 这一个月**，
2017-10 之后到 2019-01 一个正样本都没有（太阳活动极小期）。
切出来的验证集是 **0 正 / 187 负**，单类别数据集算不出 TSS/F1，
早停完全失效：

```
Epoch 1/1 | loss=0.5038 acc=0.9750 | val_ACC=0.3998 val_F1=0.5713
            val_TSS=0.0000 val_FAR=1.0000        ← TSS 恒为 0，早停无意义
```

**第二版方案（采用）**：取训练段 A 的尾部（2015 年全年）。

```python
VAL_PERIODS = [("20150101", "20151001")]
```

| | 正 | 负 | 说明 |
|---|---|---|---|
| 验证集 | 483 | 725 | 约 1:1.5，与论文训练集比例接近 |
| 训练集 | 2358 | 4342 | 正样本仅损失 17%（2841 → 2358） |

时间上不重叠（训练 2010-05 ~ 2014-12，验证 2015-01 ~ 2015-09），
避免了同一活动区的磁图同时出现在训练和验证里造成的信息泄漏。

### 最终三份索引

```
data/index/trainflare1.csv    6,700 条 (正 2358 / 负 4342)
data/index/validflare1.csv    1,208 条 (正  483 / 负  725)
data/index/testflare1.csv    12,110 条 (正  147 / 负 11963)
```

对比论文：

| | 论文 | 本项目 | 说明 |
|---|---|---|---|
| 训练集正样本 | 2988 | 2358 | 差 630，因为划了 483 个给验证集（另有边界差异） |
| 训练集负样本 | 5073 | 4342 | 差 731，同上 |
| 测试集正样本 | 196 | 147 | 实测数据本身的差异，见第四节 |
| 测试集负样本 | 11852 | 11963 | 同上 |


## 六、索引 CSV 的列结构

```
第 1 列    : 图片绝对路径
第 2–11 列 : 10 个磁场特征参数
第 12 列   : 标签（1 = 48h 内发生 M 级及以上耀斑；0 = 没有）
```

**没有表头**。

为什么用这种"朴素"结构：它是原论文代码 `utils.py` 里 `My_Dataset` 直接读取的格式，
保持兼容可以让 DataLoader 的读取逻辑与原代码一致，减少迁移风险。
读取实现在 `src/data/dataset.py` 的 `SolarFlareDataset.__init__`。
